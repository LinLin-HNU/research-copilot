日期：2026-10-07。状态：**G0 已冻结，进入 G1 实现**。用户已确认四道优先题的表述和一轮答案核查工作量；缺口判断与误判复核的边界已补齐。题集、来源及预算指纹记录于 [`WORKFLOW_G0_FREEZE_20261007.md`](WORKFLOW_G0_FREEZE_20261007.md)。G0 不调用付费模型、不调整 V1，也不把旧检索代理指标当成答案质量。候选任务保存在被 Git 忽略的 `private/workflow_g0_20261006/cases.json`；其中没有会话 ID、标准答案或论文原文。已有 72 题 `ai_reviewed_dev_cases.json` 仅作为要点线索，来源标注为 AI-reviewed，不是专家金标准。

## 为什么不能用一个“准确率”判定

研究问答没有代码测试那样的唯一通过条件。这里把验收拆成四层，分母和限制分别报告，不合成一个漂亮总分：

1. **可自动验证的硬约束（全部 12 题）**：是否访问了正确会话的论文；引用的 chunk ID 和页码是否真实属于本次可用证据；工具调用次数、证据字符和模型调用次数是否越界；异常和空证据是否终止；是否存在完整的脱敏步骤记录。这只能证明系统遵守协议，不能证明答案正确。
2. **问题覆盖（人工抽查的论文题）**：按题目中的 1–2 个子问题分别给 0/1/2 分。0=未回答或答错核心点；1=部分回答、遗漏关键条件；2=回答了可核对的核心点。参考要点只能辅助定位，核对以实际 PDF 页/证据片段为准。研究建议类题只要求“建议可检验、对照合理、与论文事实分开”，不能要求论文原文已经证明建议。
3. **论断—证据支持（同一人工样本）**：每题最多抽两条决定性论文事实，逐条给 0/1/2：0=引用不存在、无关或与论断矛盾；1=相关但不足以独立支撑，或推断边界没说清；2=引文直接支持。另记“未引用却写成论文事实”的条数。引用 ID 存在只是第 1 层，不自动得到 2 分。
4. **证据不足的诚实程度（安全控制题与不足案例）**：来源为空或确实缺少关键证据时，应明确说明不能确认，而非编造页码。正确纠正错误前提也计入；无证据时一味拒答、对有证据的问题也不作答，则在覆盖层失分。

G3 先对所有题报告硬约束、用量和逐题流程；按用户已读论文优先，预先指定 `wf-dev-01`（Informer）、`wf-dev-02`（Autoformer）、`wf-dev-04`（PatchTST）、`wf-reserve-02`（系统综述）这 **4 对旧 V1/新流程的回答**做双侧人工证据核查，不按结果挑题。评分表打乱并隐藏方案名，评完才揭盲。最小核查量是 **4 题 × 2 方案 × 1 条核心论文论断 = 8 处引用**；只有两项子问题都涉及不同事实或结果有争议时才查第 2 条，最多 16 处。这里的“处”是点击附近的证据片段/页面，不是读完 16 篇论文。若增加预算配置，还要核查**新产生或改变的关键论断**，总工作量会超过原先的一轮 8–16 处上限，必须在付费实验前重新向用户说明。若只完成这个抽样，报告只能称“试点样本中观察到的支持/覆盖情况”，**不能外推成总体准确率或幻觉率**。未完成人工抽查就不宣布答案质量赢家。

## 候选任务与划分

- 12 题：8 道开发用论文题、2 道保留论文题、1 道无论文来源控制题、1 道显式通用知识控制题。论文题覆盖方法解释、跨章节综合、局限/可检验研究建议；每题最多两个子问题。
- `dev` 题允许调试和观察；`reserve` 题冻结后只在最终关口运行一次。它们仍借用了旧开发题的 AI-reviewed 要点，**不是独立外部测试集**。
- 系统综述不在旧 72 题中，不能套用其 AI-reviewed 标准。已单独核对本地 39 页 PDF，以及归档 Chroma 中覆盖第 1–39 页的 104 块完整集合；私有来源绑定和页码锚点在 `private/workflow_g0_20261006/survey_source.private.json`。评审时优先看 PDF 第 3 页图 1B 和第 12、14–16 页的点/概率预测与评估分数，不把目录或参考文献的碰词当证据。另一份 37 块的不完整索引不用于这道题。
- 原始用户问题、来源 case ID 与论文别名留在 `private/`；评分参考和 `expected_*` 字段只供事后评审，不进入运行时 planner、retriever 或补查决策。
- 无论文与通用题用于安全/模式边界检查，不与论文题混算“答案正确率”。

## G1 的缺口判断：模型提出建议，程序约束执行，人工抽查效果

**证据是否真的充分、是否真的缺某个事实，仍由模型作语义判断，可能出错。** 程序检查字段完整、证据归属、动作和预算，不能由此证明判断正确；要求模型写出具体缺口，只是让判断可检查，也不能保证它真的具体、合理。`supported` 等状态是模型的自报标签，不是程序核实的事实。

计划节点拟先调用模型一次，把问题拆成 **1–2 个可核查子问题**，并产出首个检索查询。首次检索后，第二次模型调用逐子问题输出：`subquestion_id`、`assessment`（`supported`、`missing_specific_fact`、`truncated_context`、`conflicting_evidence`、`unknown`）、已见的 `evidence_ids`、简短判断依据、具体 `missing_information`，以及建议动作（改写检索、展开已见块或停止）及参数。依据只需可核对的简短说明，不要求或保存模型的隐藏思维链。没有相关证据时允许 ID 空集；不能用不存在的 ID 凑数。

程序独立记录是否放行及原因，检查结构、子问题 ID、证据 ID 是否属于当前论文且确已提供给模型、展开目标是否合法、动作是否在白名单、剩余次数/字符/时间是否足够。字段缺失、非法动作或预算不足会阻止执行；“模型没看懂证据”“查询虽然合法但不对题”不能仅凭这些检查识别。结构合法但语义含糊的建议可能通过，因此需要保留原始判断并事后评审。模型自报 `unknown` 或不足时，最终回答应保留未解决项。

B0 最多三次模型调用：规划 → 首轮证据后的缺口判断 → 最终综合。若执行补查，第三次模型调用结合补查结果生成答案并说明残余缺口，**不再插入一次独立的缺口判断或语义核验调用**；程序随后只做引用身份等硬检查。引用 ID 正确、模型自信、目标关键词出现，都不证明论文事实得到支持。达到调用上限是执行约束，不是证据充分的结论。

### 真实试点必须逐题留下的记录

从 G1 第一次真实运行就保存下列链条，G2 再完善展示；不能等做出结果后补写理由：

| 顺序 | 必须记录的内容 | 用途与边界 |
| --- | --- | --- |
| 已见证据 | request/case ID、语料与配置指纹、子问题、**模型当时实际收到的片段**、chunk ID、页码、截断/展开范围、顺序、片段内容指纹 | 人工判断当时是否已经够用；只存原始整块 ID 无法重建截断后的实际输入 |
| 模型判断 | 模型/提示词版本、原始结构化输出与解析结果、每个子问题的自报状态、已见证据 ID、简短依据、缺失信息、建议动作及参数 | 原样保留错误或非法建议；不把“模型声称充分”显示成“系统已验证充分” |
| 程序放行 | allow/deny、具体检查结果与原因、剩余预算、动作是否真正执行 | 结构/动作非法、外部或未见证据 ID、预算耗尽、超时等与模型语义判断分开 |
| 补查结果或停止 | 实际查询/展开目标、返回与最终纳入的证据 ID 和文本范围、去重/裁剪、空结果/错误、耗时及实际 token；未执行则保留停止来源 | 区分模型主动停止、预算/超时强制停止、校验拒绝、工具失败；同一 ID 展开后也可能新增有用内容 |
| 最终结果与复核 | 最终答案、论断—引用映射、未解决子问题、原始停止原因、人工标签/依据/复核范围 | 新证据是否有用、是否改善答案，由人工抽查；未评审记 `not_reviewed`，无法判定记 `uncertain` |

完整片段仅保存在 Git 忽略的本地私有评测产物中，供用户核对；常规日志/公开报告只放脱敏 ID、指纹、计数、状态和经检查的示例，不含密钥或整库原文。缺失 usage 记未知，不补成 0。截至 2026-10-07，G1 的离线内核已实现私有逐步记录并通过合成示例；**尚未接入真实模型或获得真实论文结果**，具体状态见 [`../../docs/单Agent工作流-G1进展-20261007.md`](../../docs/单Agent工作流-G1进展-20261007.md)。

### 两类误判的人工判定口径

1. **不必要的补查：** 人工先阅读首次实际证据，确认本题所需事实已经足够、有可定位支持、也没有需要解决的冲突；模型却声称缺少这些事实并要求补查。若动作执行，记录其额外调用/耗时/token；若被程序拦截，记“多余补查建议被拦截”，不算已执行补查。首轮确实不足但补查没有找到信息，记“有必要但未成功的补查”，不能直接算多余。重复 chunk、未新增 ID 或未命中关键词均不能单独作判据。
2. **本应补查却提前停止：** 模型主动判定某子问题已充分并停止，人工发现当时证据缺少回答所需的关键事实，且程序原本允许继续行动，记“充分性误判/可继续时提前停止”。若进一步在同一可用论文中定位到缺失事实，并确认属于允许的检索/展开范围，再记“存在可补查的原文依据”；这仍不证明那次搜索一定能找到它。原文是否含该信息无法确定时保留不确定标记，不能为了形成错误率硬判。预算/超时/非法输出导致的停止另归执行原因；诚实说明不足也与错误声称充分分开。诚实停止是否错过合理补查机会，可作单独观察，不自动认定为错误。

“判断是否合理”“动作是否成功”“最终答案是否正确”分别评审：合理补查可能检索失败，多余补查也可能碰巧改善措辞，模型误判停止后也可能依靠已有知识答对；这些结果不能互相替代。

人工抽查仍优先覆盖原定四题。答案盲评先完成，再展示新流程的判断轨迹，避免流程信息提前揭盲。轨迹复核先看问题和首轮证据，给出“充分/不足/不确定”及依据，再看模型建议和实际执行结果，减少结果倒推判断。每题增加一次简短决策复核，确实会增加阅读判断的时间；原先 8–16 处是**答案核心引用的上限**，不能声称它同时包下所有缺口审计。额外翻页寻找遗漏事实按需记录，不能确认就标不确定，不要求用户通读论文。四题中某一分支没有出现，就报告“该分支无人工真实样本”，不为补齐样本伪造或遮蔽证据；追加真实人工样本需单独列明工作量。

报告同时列全部真实题的建议/执行补查数、主动/强制停止数，以及人工抽查中两类误判的逐题标签。仅在对应分支可判定的人工样本内列分子和分母：如“不必要补查 x/n（已执行且人工可判定的补查）”“充分性误判 y/m（仍可继续却模型主动报充分并停止、且人工可判定）”。拦截的建议、未评审和不确定样本另列；分母为 0 时显示“无可判定样本”，不能显示 0% 错误。不外推总体缺口识别准确率，也不以补查触发率冒充质量提升。

### 离线测试能证明什么

fake LLM/检索器用例证明状态转移、字段/来源校验、动作约束、预算和留痕可运行。应同时覆盖“模型漏看已有证据而合法多查”和“模型错误报充分而合法停止”：程序可能放行，测试要求其保留原判断和执行事实，**不能偷偷用测试标准答案在运行时纠正模型**。预设正确判断的离线用例不是模型理解真实论文的能力证明。真实缺口判断质量须由以上逐题记录与人工抽查给出；G1 通过只表示受控工作流跑通。

## 对照与判定口径

- **固定对照条件：** 旧 `v1_current` 的现有路由/预检索流程不改，新模式单独运行；两者使用同一任务文本、同一个归档 Chroma 快照及指定论文集合、同一模型/端点、temperature=0、max_retries=0、最终答案 `max_output_tokens=1200`。V1 产品默认上限更大，因此这里是**统一参数的评测版 V1**，不能混称线上生产延迟。执行次序交替或随机记录，失败不静默重试；每题的来源指纹、调用参数和实际 usage 入私有 manifest。
- **硬预算：** V1 沿用每块 600 字、最多 8 块、总证据 6000 字。新模式第一次最多装约 4000 证据字符，整个请求最多 8 个唯一块、6000 证据字符、2 次检索/展开动作、3 次模型调用（规划、缺口判断、最终答案）；三次模型输出分别最多 400/400/1200 token，单次模型超时 60 秒，总请求硬期限 180 秒。超限必须停或降级并记录原因；实际输入 token 与费用按 API usage 报告，**字符上限不等于输入 token 或账单硬上限**。正式付费前另向用户列出最多调用次数与费用风险，并取得当次授权。
- **什么算完成：** “流程完成”只表示产生了带停止原因的最终输出且预算/隔离/引用身份约束均通过；“研究任务完成”还要求人工抽查的 1–2 个子问题得到有支持的回答，或确实无证据时有合理的不足说明。引用 ID 存在但语义不支持不能算任务完成。论文事实与模型提出的实验建议要分开评审。
- 旧 `section_hit`、`term_hit`、`strict_proxy_hit` 只作为**检索诊断附录**，不参与任务成功或引用支持评分。先看逐题质量与失败，不按旧代理分数更改新评分尺。
- **改善/退化如何判：** 同一题的人工覆盖和证据支持均不下降、至少一项上升，且没有新增无支持的论文论断，才记“质量改善”；任一项下降或新增无支持论断，记“退化”；一项升一项降记“权衡”，不硬选赢家。成本和延迟另列，不并进质量分。报告展示所有 12 题的流程结果和 4 对抽查题的匿名评分；只报告计数与案例，不做显著性或普遍优越性宣称。即使四题表现好，也只考虑深度模式保持**可选**，不自动替换快速 V1。
- 继续开发的硬门槛是所有预算/隔离/引用身份测试通过、没有伪造来源；另用**受控离线缺口用例**证明“预设的缺口建议→合法补查→输出或停止”的分支可运行，并覆盖语义误判仍可合法通过的情况。该门槛不证明真实缺口判断正确。真实题的 trace 要如实报告是否触发补查及人工是否认可该判断；若未触发，不能宣称已在真实任务中验证自主补查，也不能为展示补查而故意遮掉可用证据。是否把它设为默认模式，要等 G3 用户阅读质量/成本对照后决定；不预设一定胜过 V1。

## 预算迭代：先 B0，再按失败原因只改一类约束

用户希望在回答质量与实际 token 消耗间找平衡。先用上面的配置作为 **B0** 跑一次开发题并保存逐题答案、trace 和 API usage；这不是“最优预算”的先验结论。之后根据 B0 的具体失败选择**至多一个**主要放宽方向，而不是同时放开所有上限：

| 观察到的瓶颈 | 候选下一轮 | 保持不变的条件 |
| --- | --- | --- |
| 已找到相关块，却因最终块数或证据容量没装进回答 | B1-E：最多 10 个唯一块、总证据 8000 字；每块仍最多 600 字，工具 2 次、模型 3 次 | 同题、同语料、同模型和输出上限；报告新增字符与真实 token |
| 候选池始终没找到需要的信息，且有具体可改写的缺口 | B1-A：检索/展开最多 3 次、模型最多 4 次；块数仍 8、总证据仍 6000 字；第 3 次动作前再做一次至多 400 输出 token 的缺口判断，总期限相应预设为 240 秒 | 不扩大证据容量；报告是否真的找到新证据及额外调用成本 |
| 已找到的相关块仅在 600 字截断处丢失关键句 | B1-X：只允许定点展开该块至 1200 字，仍占一次动作并遵守原有 8 块/6000 字总上限 | 不全局把每块都改成 1200 字，避免挤掉其他块 |
| 失败与预算无关（错误章节、PDF 噪声、错误论断） | **不加预算**，记录其他故障并停下预算搜索 | 不用更多 token 掩盖检索或解析问题 |

每次只在 `dev` 题上与 B0 **成对重跑**，列出改善、退化、用量中位数/范围及触发预算的题；最多做两轮有理由的调整，到期停止，不无限循环。`reserve` 两题只在配置冻结后各运行一次，不参与调预算。由于先前同块对照中 8 块×每块 600 字的最终证据都少于 6000 字，**只把总上限从 6000 提到 8000、却不增加块数或展开长度，预期不会产生新证据**。选择的是这些被测配置中的“质量—消耗折中点”，不是统计意义上的全局最优；小样本差异不够清楚时保留 B0。

## G4 所说的完整回归

不仅重跑 `python -B -m unittest discover -s tests`；还要逐项检查原有上传/解析/索引、快速问答、历史与换论文清理、论文/通用路由、SSE 响应、请求级指标都没有被新路径破坏。新路径再测空库、错误会话、重复证据、工具异常、非法模型输出、超时、预算耗尽、引用不存在和证据不足。先离线 fake LLM/检索器，必要的真实 API 小样本由用户单独批准并执行。若 Docker Engine 可用，再做本地 Compose 起停和浏览器烟测；这仍不等于公网部署。
