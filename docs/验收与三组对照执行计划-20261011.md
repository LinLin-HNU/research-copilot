# 当前版本验收、Trace 与 Eval 执行计划

本文件是 2026-10-11 的当前执行入口；早期 G0/G1 文档属于历史协议，不自动套用到全文阅读路径。目标是稳定、可解释地交付，不预设新工作流一定获胜。

## 已完成与仍待验证

- 统一 `/chat`、旧路由、新研究入口的生成模型配置和客户端构造；同一服务使用同一生成连接，temperature=0、自动重试=0。各阶段保留自己的输出上限。配置修改后需重启，旧 V1 冻结分支不修改。
- 嵌入模型仍独立使用 DashScope。换生成模型不需要重建向量库；更换嵌入模型或向量维度需要新建并重建索引，不能混用旧向量。
- Sundial 历史结构化试跑抽取 JSON 不完整，随后直接全文生成。它证明降级分支可运行，不证明结构化讲解提升。新版紧凑资料表需真实试跑确认 `reading_brief_used=true`、出现 `structured_context`，之后再核对质量。
- 自动自评分不得触发循环重写。资料表抽取失败后的有界降级与自评分重写不同；成功返回也不能隐藏原先失败及两次调用成本。
- 公网鉴权、限流、部署降级留到发布阶段；现有保护保留。此次不实现每用户在线提交 API Key。

## 测试分层

### 白盒：程序是否遵守约束

离线 fake 模型/检索器覆盖状态转换、模型配置隔离、非法 JSON、输出截断、引用 ID、原文摘录、工具白名单、重复证据、预算、超时、失败留痕及失败后不无限重试。模型提出语义错误但格式合法时，也要保留轨迹，不能偷偷拿标准答案纠正它。

完整运行 `python -X utf8 -B -m unittest discover -s tests -q`。记录提交号、环境、通过/失败/跳过数。通过不代表模型论文理解正确；此次不宣称代码覆盖率或全场景验证。

2026-10-11 本机实测：160 项全部通过（0 失败、0 跳过），未调用新的付费 API。新增3项验证共享工厂、旧配置入口和路由参数继承。GitHub Python 3.12 CI 的结果需推送后另行查看，不能用本机结果替代。

### 黑盒：用户操作是否完成

关键操作表：导入有效 PDF→选中→提问→追问→换论文；空问题/损坏或超大 PDF；错误令牌、错误会话；全文超界；上游认证失败、超时或非法输出；用户可见失败提示能否关联管理员 Trace。确认论文隔离、历史不串、正文可读、指标不泄漏到用户页面。离线 TestClient 属于模拟接口验收，需另做真实浏览器和实际模型试点。

### 语义验收：答案是否值得使用

按题核对核心要点、事实支持、无支持论断和不确定性说明。页码或 ID 存在只证明引用身份，不证明语义支持。`ok/partial` 是执行/输出状态，不当作准确率。LLM Judge 只辅助提示疑点，人工不确定就保留不确定。

### 发布验收（最后执行）

Docker Engine→Compose build/up→页面/导入/问答→重启后 SQLite、Chroma、Trace 保留→停机。之后才做公网认证、用户数据隔离、密钥管理、HTTPS、持久化限流等检查。完成本机容器验证不等于上线。

## Trace 和 Eval 分开整理

Trace 回答“发生了什么”：请求 ID、模式选择、实际模型/端点、历史指纹、已见证据、模型缺口建议、程序放行理由、工具动作、补查结果、停止原因、原始响应、输入输出与缓存 Token、耗时。缺失 usage 标未知，不记成零；摘要和 ID 核验不当作语义核验。

Eval 回答“做得怎么样”：冻结题目/论文指纹/版本/参数，匿名答案，逐题评分、核心引用支持、改善/退化/权衡、费用与延迟，已知局限和发布决策。现有请求 Trace 与 pilot 有留痕，不等于所有生产请求已支持断点恢复、幂等执行或完整可复现回放。

原始资料和模型答案放 `benchmark/experiments/private/`，不上传 GitHub；公开只放脚本、协议、脱敏汇总和合成样例。管理员查看现有 Trace 页面，用户只读自然讲解与可展开来源。

## 8 题三组对照：先确认，不立即付费

三组：冻结 V1 的路由与预检索逻辑（控制参数评测版）、当前默认自适应流程、直接全文生成。两种全文路径可能相同；这本身就是模式选择的结果，不强行制造不同。核心是看局部问答/补查是否在质量与成本上有价值。

同一论文索引与模型、题目、temperature=0、重试=0、fresh 历史、相同回答深度与最终输出上限。固定审阅器关闭以隔离问答路径；结构化资料表不混进主实验。各流程允许不同证据量，报告真实输入消耗，不能把更多证据的收益归因于 Agent。执行顺序交替，失败不静默重跑。先确认输出上限是否足够，冻结后不按题临时放大。

候选题（用户确认后，私有 manifest 冻结；不是专家金标准）：

1. Informer：主要问题与三项核心贡献，各解决什么问题。
2. Autoformer：分解与 Auto-Correlation 如何协作处理趋势与周期。
3. PatchTST：patching 的输入/输出变化及 channel-independence 的含义。
4. FEDformer：频域模块的作用，不能把频域处理等同于简单滤波。
5. TimesFM：decoder-only 模型训练与预测链路，以及零样本含义。
6. 系统综述：point forecasting 与 probabilistic forecasting 的区别和对应评价指标。
7. Informer：核查“生成式解码器会逐步把真实未来值作为输入”这个前提是否成立。
8. FEDformer：作者明确承认的局限与读者推断的改进方向分开列；原文不能确认就说明未确认。

现有读过论文大多已用于调试，这轮叫开发验收，不冒充独立测试集。以后追加未用于调参的论文/题目再报告泛化。8 题×3 组=24 个最终答案，不等于24次模型调用；执行前脚本必须列最大模型/嵌入调用数并取得当次费用和数据发送授权。

核心人工核查最多每答案2处重要事实，共最多48处，可先评4题，再决定另外4题；匿名先评答案，之后看流程。标签：改善、持平、退化、权衡、不确定。增加无支持论断或关键事实退化不能用“更长”抵消。成本独立报告，不凑一个总分。每题失败保留；配置冻结后只按明确 bad case 修一轮并成对回归。

## 用户参与与阶段门禁

1. 保存与配置：我提交推送实验分支并跑离线测试；你确认默认生成模型和端点，不展示密钥。
2. 资料表：我准备新输出目录与指令；你授权并运行一次小试点，检查实际进入结构化路径。失败先定位，不重复烧额度。
3. 冻结：你确认默认策略、深度、题目和审阅工作量；我记录配置与哈希。不能用模型自评分自动选默认。
4. 对照：你执行付费命令；我整理匿名答案、Trace 和逐题结果，你核查熟悉论文的核心事实。
5. 收尾：只修有证据的故障、回归、Docker 本地验收；质量差异不清楚就保持简单默认，不无限调参。

## 侧边聊天（核心验收后）

侧边会话挂主会话 ID，发送已确认的最近主问题/回答与有上限的摘要；摘要带版本和来源请求 ID，不当论文事实依据。用户显式设置知识基础/读过哪些论文，可编辑删除；不要自动推断并永久存储。默认单向读取主会话，侧边讨论不自动污染主历史。旧论文切换时上下文隔离。压缩保留关键定义和未解决问题，精确论文事实重新检索。实现后验收“更新、隔离、可编辑、压缩遗漏”，而不只看界面出现。

## 简历和面试的表达边界

可讲实现：受控检索/展开、配置隔离、阶段 Trace、引用身份校验、预算与失败留痕、离线回归和冻结对照设计。可讲已测：实际测试数量及命令、已完成的逐题实验结果。不可提前写：自动核验证据充分、提高准确率、生产上线、全链路断点恢复。

面试口述链路：固定预检索可能漏掉关键证据→引入受限补查并保留直接全文基线→Trace 区分候选未召回、截断、错误动作与非法输出→离线测约束、真实题测语义和成本→据改善与退化决定保留哪些机制。
