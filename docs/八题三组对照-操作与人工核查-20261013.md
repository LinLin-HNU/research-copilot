# 八题三组开发验收：操作与人工核查

## 本次准备边界

只做离线准备、假模型验证和私有索引预检，不批准付费运行。旧V1取release/v1-freeze-20261002解析出的提交快照，保留路由、检索及系统提示词；仅用受控单轮适配器统一连接、temperature=0、重试0和最终输出上限6400。不是直接调用旧网页，也不把适配器延迟称为线上端到端性能。

当前自适应组strategy=auto；直接全文组strategy=deep且预检全文符合既有100000字符/200块限制。两组都关闭资料表和辅助审阅，fresh历史。新路径保留输出截断的部分回答策略，partial不自动判失败；旧V1输出格式与新JSON格式不同，统一输出上限并不意味着可见正文长度一致，需报告这个差异。

## 待用户确认的八题

第一批：Informer主要问题/三项贡献；Autoformer趋势与季节方法链；PatchTST patch与channel independence；FEDformer分解与频域模块分工。
第二批：TimesFM链路及零样本边界；综述点/概率预测评分；Informer真实未来值输入的错误前提核查；FEDformer作者局限与读者推断区分。

完整题目与核查重点在私有实验目录questions.md，不含专家gold。题目用过的论文都已参与开发，这轮叫开发验收，不报告独立保留测试集准确率。

## 预检结果与限制

四题三组共12个合成输出已跑通，旧V1执行实际冻结函数，模型和检索用fake。另用已有1024维向量在私有副本上测试冻结V1检索，四篇各选8候选；不调用embedding，不是检索准确率。

系统综述不符合当前全文输入限制，因此第二批的直接全文组会记录not_applicable，不偷偷截断全文、增大预算或冒充RAG全文组。其余组仍可回答。完整实验最多24个结果槽位，但不保证24份有效论文答案；应单独报告不适用/失败/部分输出。第一批四篇全文均可用。

论文文本、SQLite、HNSW文件复制到私有副本，SQLite采用只读连接事务backup。复制索引文件时应暂停导入；运行前重新校验文本指纹。源码、题目、原文、提供商与输出预算变化后拒绝运行原实验目录。索引预检只能证明该副本目前可查询，不能保证任意并发导入时复制一致。没有生产数据库/会话历史写入。

## 费用和失效保护

每题三组最多6次模型调用（旧V1 2、自适应3、直接全文1），另有最多8次embedding请求。第一批最多24次生成/路由/判断等模型调用、32次embedding请求；八题合计最多48和64。上限不等于预计实际量或金额。embedding上限包含查询扩展引发的请求，耗尽时停止并记录；不把这种执行失败混作回答错误。

授权目的地：冻结的生成服务商（当前api.deepseek.com/deepseek-flash）与独立DashScope embedding端点。生成可发送相应全文/片段和问题，embedding发送查询文本，不发送标准答案。须另取得当批数据发送和费用授权。服务商拒绝后停止批次，不自动重试。失败响应原文及计费unknown不覆盖。批次一旦.started，禁止重复运行；任何恢复要先核查完成记录和未知计费，本脚本没有自动恢复。

## 用户确认后的执行顺序（现在不要执行run）

1. 确认八题表述、第一批范围和每份最多两处核心事实核查（12份最多24处）。如果改题，重新准备新目录，不修改已冻结manifest凑分。
2. 用户执行approve，记录已确认题目与工作量；approve不调用API。
3. 用户对当批费用/数据发送确认后执行run --batch 1 --confirm-paid；它调用API，不需启动uvicorn。
4. 完成后打开review_batch_1/answers.html，先不要打开mapping.private.json或operations.private.json。review.json为评分草表（暂用JSON，不是在线打分器）。
5. 先匿名核查答案，之后揭盲看Trace和成本；仅报告已评样本。未知项保留null/不确定，不填0冒充已评。

人工字段建议：readable_answer布尔；supported_core_facts写已核查且有支持的0–2处，不当全回答准确率；unsupported_claims写已确认无支持的论断数，其余疑点写notes；core_coverage写complete/partial/missing；uncertain布尔或null。每份notes注明核对的事实和页码/章节。当前脚本没有自动评分或宣称专家正确率，也不会按自评分重写。

对每题比较三份回答，标改善/持平/退化/权衡/不确定，事实错误优先于完整性；额外检索是否值得看实际内容与成本，不能只看关键词。第一批评完再决定第二批，不预设新流程获胜。

## 公开与私有

公开：脚本、合成单测、协议。私有：论文、答案、Trace、映射、源库副本、含本机路径的运行材料与凭据。源码修改后重新准备；Git提交本身不改变冻结的文件hash。旧V1与main不合并、不删除原文数据。
