# 输出截断降级与三组对照口径

## 用户优先级

优先提供可用、有依据的部分回答，不为覆盖全部内容编造事实。完整性可以通过继续追问补充。来源身份和格式校验不等于语义正确性；不承诺模型绝对无误或每次故障都能给出论文结论。

## 到达6400时的行为

上限由服务商执行，通常以finish_reason=length结束；6400包含完整JSON，而非仅可见正文。如果被截在JSON中间，旧流程直接停止、没有正文。

新逻辑只对最终全文writer/结构化writer/RAG final的output_token_limit恢复完整JSON条目，保留现有字段、长度和本请求来源ID校验。没有补闭括号、拼残缺文字、猜公式或新增模型调用。非法引用或字段的条目逐项拒绝并留痕。

有可保留条目时：status=partial、stop_reason=output_token_limit_partial，正常展示已有回答，单独提示输出未完成及继续追问；不把长度不够误称原文证据缺失，也不继续调用辅助审阅。

没有任何完整且通过身份校验的条目时，保持明确停止说明；普通非法JSON、认证失败、超时、真实输出超预算违约不是这次prefix恢复的适用条件。新机制不证明残留条目的语义准确。资料表抽取不能使用答案前缀恢复，仍使用原有有界降级。

通过8项新增离线测试，涵盖残缺句、转义/嵌套字段、无效引用、缺引用、完整正文但footer截断、超大条目、全文/RAG调用数、资料表不误恢复。本机完整回归181项通过，无失败/跳过，使用禁止外部连接的runner，无新付费调用。

## 三组对照不是只比较输入长短

1. 旧V1：固定路由、预检索、章节/证据策略，再生成。
2. 当前自适应：整体讲解可全文；局部问答可RAG并受限补查；最终生成。资料表实验开关关闭。
3. 直接全文控制：强制把同一论文可用全文交给同一模型，直接生成，不规划补查。

固定题目、论文版本、生成模型、深入深度、最终输出上限6400、fresh历史、重试0，辅助审阅关闭。证据输入和调用次数允许不同，这是被比较的机制；实际Token、缓存、延迟和可见正文长度分别报告。旧V1仅适配连接/输出参数以控制变量，不修改冻结的路由和检索算法。八题含六篇已读论文，属于开发验收，不冒充独立专家测试集。

新系统整体题选择全文时可能与第三组采用同一路径，不制造虚假的Agent收益；局部题重点检查RAG是否能降低输入成本且不损失重要事实，補查是否有效且值得额外调用。

主要观察：有没有可读输出、核心事实是否有支持、有没有错误或无依据论断、核心要点覆盖、Token和耗时。partial不自动判失败；截断但有效部分正确，单独记录部分输出与覆盖欠缺。LLM审阅不作为自动重写或金标准。输入更多导致覆盖更高不能直接算Agent改善，只有逐题核查后报告改善/持平/退化/权衡。
