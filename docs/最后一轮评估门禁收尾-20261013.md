# 最后一轮评估门禁收尾

## 已实施

1. refuted_premise表示当前论文证据反驳用户前提；必须引用当前已见ID，缺失信息可为空。conflicting_evidence只用于论文证据内部冲突。程序仍不能证明模型分类正确。
2. 子问题逐个检查；字段错误的子问题单独记录，合法子问题进入最终写作。发生评估降级时不执行全局补查动作，避免动作对应错误的子问题。原评估、有效动作、blocked_subquestions保存在Trace，公开答案列出可单独追问的问题。
3. 全部评估/顶层结构不可用时，禁用补查，给最终写作提供unknown评估及assessment_unavailable标志，仅基于已经取得的当前论文证据作有限解释，标partial，不伪装为评估通过。跨论文/未见引用仍硬性失败。
4. supported同时填写缺失信息时仍归一化为missing_specific_fact，保留normalized_from；缺口不代表禁止最终回答。
5. stop只结束补查，不结束问答。程序不再因显式缺口强制改成search；最终正文和coverage披露剩余缺口。模型合法提出search/expand才在既有白名单、次数、时限与预算内执行；预算不够仍进入最终有限回答（如果有剩余模型/时间预算）。
6. 原低收益展开改为搜索的规则不在本轮全面重做；仍保留预算与Trace记录，不能宣称所有程序动作都完全听模型。
7. 显示标题改为“当前证据边界与待核实内容”。允许基于证据与领域理解判断错误前提，推断标inference；不能把通用知识冒充原文事实。

## 已验证与未验证

合成用例覆盖refuted_premise、单题异常隔离、整份坏评估、无缺口搜索被禁止但继续写作、supported附缺口停止补查、跨论文引用仍拦截。原第二批Informer评估离线回放保留q2，q1列为missing_information_required，不产生新模型答案。原实验仍计失败；不修改旧manifest、答案或计费记录。

并非专家准确率，不保证真实模型未来正确分类，也不保证最终生成不会再次出JSON/引用错误。没有扩大检索算法、候选池、模型调用或费用授权。定义漏检仍是已知质量局限。

## 未来检索（仅讨论）

先区分原文解析缺失、正确段落未进候选、排序/融合淘汰、预算截断、模型读错。BM25可补精确术语/缩写，Dense可补语义同义表达；融合得到共同候选后，Cross-Encoder用于相关性重排。重排无法找回从未进入候选的段落。先有真实相关块标注的小样本，比较候选覆盖与最终证据覆盖、成本和退化，再决定是否引入模型依赖。不要直接以词项命中替代事实支持。

## 下一步边界

结束本轮消融/问答优化；保存可逆版本、整理两批开发验收与已知失败，随后Docker本地验收。真实修复效果如需验证，由用户另执行限定单题，不重跑八题整批。公开部署、安全生产化另立边界。
