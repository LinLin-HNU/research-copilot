# Docker 本地验收

新路径使用实验分支，Compose文件独立使用，不与其他文件叠加。项目名research-copilot-acceptance，镜像research-copilot-acceptance:local，宿主127.0.0.1:8020，容器8000。仅本机访问，不是公网部署。

旧容器属于主Research_Copilot，挂载主项目resources。本轮不启动、删除、覆盖它。新容器使用实验工作树resources，与主项目目录分开；应用运行会正常写入实验数据，因此真实导入/问答前仍应按需要备份。容器内部private映射到docker_acceptance_runtime，用于持久化Trace及相关运行文件，不挂入旧评测答案。

凭据通过本机.env注入，不进入镜像。关闭额外辅助审阅RESEARCH_QUALITY_REVIEW=0。构建会联网下载基础镜像和Python依赖，但不是调用论文模型；后续导入会调用嵌入API，问答会调用生成/嵌入API，需要用户分别执行并知悉费用。

## 用户执行节点1：构建并启动

在实验工作树运行：

```powershell
docker compose -p research-copilot-acceptance -f compose.acceptance.yaml up -d --build
docker compose -p research-copilot-acceptance -f compose.acceptance.yaml ps
```

首次安装依赖可能较慢。失败时保留错误，不使用down -v、不删除旧容器或数据。

## 节点2：无付费页面检查

浏览器打开 http://127.0.0.1:8020/research 和 http://127.0.0.1:8020/admin/research 。根路径/仍是旧聊天页，不能以看见旧页判断新版没部署。填入本机研究入口Token，勿贴出密钥。先验证页面、鉴权和论文列表，不自动执行生成。

## 节点3：用户另行执行真实验收

限定导入、整体讲解、局部追问、管理员Trace。先说明所用论文和发送/费用边界再执行；原有论文可以先复用减少嵌入费用。Trace查看模式、工具动作、Token和停止原因，不将status当事实准确率。

## 节点4：持久化

记录论文ID、请求ID，然后对本验收项目重建/重启，验证论文与Trace仍在。没有执行这一步前，不宣称重建持久化已验收。不要对旧V1做任何清理。

本文件为准备与操作说明；构建、运行和真实问答结果需后续分别填写，不预先宣称部署成功。
